## Architecture and execution paths

Both apps use Next 16.3.3, React 19.2.8, Prisma 6.19.3, TypeScript, Tailwind 4, NextAuth, Paystack, Cloudinary and Resend. No new vendor SDK is needed. Pages invoke Axios APIs under `/api/marketplace`; controllers validate sessions/ownership/admin access, call domain services and map ServiceError to HTTP errors. The target has additional E-Learning, AI, productivity, academic and administrative modules, a separate E-Learning Prisma client/database, and shared notifications. None of their schemas, routes or services should be replaced.

Reference storefront routes are rooted at `/`; target storefront lives under `/studashboard/marketplace`. Reference `/admin` maps to `/studashboard/admin/marketplace`. Keep the main student DashboardNavbar and admin parent layout. Reference's independent mkt.* cookies, sign-in throttling, identity marker, restricted database startup verifier and independent sessions are application boundaries, not replacements for AkadVerse authentication. Marketplace blocks must deny Marketplace access without signing the user out of academics or E-Learning.

Public Business(type BUSINESS/SCHOOL_VENDOR), Product/images/variants, Side, CartItem, Order/OrderItem/Event, CheckoutPayment, Deliverer, Delivery/DeliveryItem/Delivery_x_businesses, VendorDeliveryBooking/Slot/capacity/date overrides, Notification, EmailDelivery, AdminActionLog and MarketplaceSettings are shared rows in the Core database. Existing AkadVerse public models are authoritative. Existing public fields/enum values and unrelated relations must be retained.

Reference extension schema `marketplace` holds account state, recurring roster settings/slots/weekly assignments/date exceptions/saved delivery plans, booking handover codes/submissions, briefing notices, physical card handovers, shift check-ins, overdue confirmations, business delivery prices, business pricing settings and immutable checkout snapshots. They must remain those same schema-qualified tables when both apps run on the same database. No second inventory, payment, order, user or personnel system.

Business checkout groups by business, computes integer-kobo quote and slot selection, validates reviewed quote under an operation advisory lock, reserves stock conditionally, and atomically writes orders/payment/snapshot/plans. Child Order.totalAmount remains item subtotal. A single flat checkout fee plus per-business delivery fees lives in CheckoutPayment.amountKobo and immutable financial snapshot. Missing prices block purchase; no default delivery-price backfill. The reference's current minimum is **two Lagos calendar days**; its older DELIVERY_SCHEDULING_REPORT says three and is stale. Preview is advisory, initialization rechecks, stale quotes return 409 and require renewed confirmation.

Vendor checkout remains a separate Serializable/retry workflow: one booking per multi-vendor checkout, chosen date/time, independent vendor prep capacity and roster capacity, minimum two-hour strict order cutoff. Paid vendor orders auto-accept and become assignable without vendor readiness/pickup OTP. Delivered status requires the student's booking-bound six-digit code, online or queued offline. Business seller acceptance/drop-off/pickup/buyer OTP workflows remain separate.

Server Paystack verification of amount/currency is authoritative. Webhook/browser/reconciler compete through conditional payment transitions; expired holds release stock once, late success rechecks capacity and routes conflicts to NEEDS_REVIEW. Payment settlement must tolerate another app having marked the same orders paid, without duplicating emails/events. Refund services currently record internal refund state; this is not proof of a real Paystack reversal. Seller payouts and deliverer payout runs retain existing separate rules.

New delivery codes use booking-bound HMAC, timing-safe comparisons and AES-GCM ciphertext, with a dedicated shared DELIVERY_CODE_SECRET preferred over independent NextAuth secrets. Students see their full code; staff see a partial mask. Submission IDs support replay protection, rejected attempts are limited, late arrival is judged by server receive time and recorded; admin fallback requires the real student code and an audit reason. Do not log codes or persist submitted plaintext.

Notifications reuse existing writers/outbox/SSE. New transactional notices use deterministic IDs and publish after commit/read. Shared scheduled jobs must have one owner per database. Existing target Vercel daily inventory/schedule and AI jobs are retained. Reference vendor-slot-briefing already runs independently: do not silently enable a second scheduler here. Review job ownership before switching it.

## Final database integration decision

`prisma/schema.prisma` is unchanged from the initial clean target. The standalone schema-sync script unconditionally injects schema annotations and extension relations, so adding those to its input would break generation. Instead `scripts/generate-core-prisma.mjs` composes the authoritative public schema with `prisma/marketplace-runtime/extensions.prisma`, injecting only runtime schema metadata and two cross-schema relations. It generates ignored `prisma/marketplace-runtime/schema.prisma` and one extended `@prisma/client`. Existing Core and Marketplace services still share the same singleton and transaction client. No duplicate database tables/client pools or cross-client pseudo-transactions are introduced. Existing E-Learning generation remains independent.

Public migrations continue at `prisma/migrations`; Marketplace SQL remains at `prisma/marketplace-schema/migrations`, with its existing `marketplace._prisma_migrations` history. Never migrate/db-push the runtime union. The reference `schema:check` passes after this adjustment. Standalone application source/configuration remains unchanged.
