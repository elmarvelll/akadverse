# Decision: HOD's result-upload approval moves SUBMITTED directly to PUBLISHED

- **Date**: 2026-09-14.
- **Context**: §32 names a five-stage result workflow: `DRAFT → SUBMITTED → VALIDATED → APPROVED → PUBLISHED`. §23 says "HOD should also be able to approve result uploads submitted by faculty." No section assigns a role or a screen to the `VALIDATED` or `APPROVED` checkpoints specifically, and no section says who performs the final publish step.
- **Problem**: Build the two (or more) intermediate approval screens the five-stage name implies, guessing at who performs each and what distinguishes "validated" from "approved" — or treat "HOD approves" as covering the whole gap between a faculty submission and a published, student-visible result.
- **Chosen option**: `services/e-learning/hod/result-approvals.ts#approveResultUpload` moves every `SUBMITTED` result for a course directly to `PUBLISHED` in one HOD action. The `VALIDATED`/`APPROVED` values still exist on the `ResultStatus` enum (so a real intermediate stage can be added without a schema migration) but nothing currently writes them.
- **Reason**: §39 explicitly warns against building models/workflow stages the actual described workflow doesn't call for ("build the schema around actual workflows"). Inventing a second approval role or a two-click HOD flow to fill an unspecified gap would be adding scope not actually requested, on a guess about who's supposed to do it.
- **Consequences**: There is currently no separate "validated but not yet approved" state visible anywhere in the UI — a result is either still with faculty (`DRAFT`/`SUBMITTED`) or fully published. If a real distinct validation step is specified later (e.g. DAPU validates before HOD approves), it slots into the unused `VALIDATED` state and `approveResultUpload` splits into two functions without a schema change.
- **Alternatives rejected**: A DAPU-side "validate" step before HOD's "approve" — not built, since §25-§28 (DAPU's own section) describes course structure, time frames, and timetable, never a results-validation responsibility.
