# Decision: DAPU's "Course Structure" is direct course-catalog CRUD, not a staged workflow

- **Date**: 2026-09-14.
- **Context**: §26 describes DAPU's Course Structure responsibility as three steps — Receive Structure, Review Structure, Send to HOD — over a hierarchy of Faculty → Department → Program → Level → Semester → Courses.
- **Problem**: §26 never specifies what artifact is actually "received" (a file? a form? from whom?), what changes about a course between "received" and "reviewed," or what "sending" to HOD actually does beyond making it visible. There's no separate staging/intake model described to receive *into*.
- **Chosen option**: `services/e-learning/dapu/course-structure.ts` manages the `Course` catalog directly — `createCourse` ("Receive Structure"), `listCourses` ("Review Structure" and, department-grouped, "Send to HOD"). A course is visible to its department's HOD (for lecturer assignment, §22) the instant it's created; there is no separate "not yet sent" state.
- **Reason**: `Course` is already the concrete, spec-required artifact HOD needs (§22's lecturer assignment operates on courses directly). Modeling a separate `CourseStructure` staging entity with Received/Reviewed/Sent states, with no spec'd shape to base it on, is exactly the kind of guessing §39 warns against ("Do not blindly create every model before analyzing relationships... build the schema around actual workflows").
- **Consequences**: The three nav items (Receive/Review/Send to HOD) map to three views over the same underlying data rather than three distinct pipeline stages — "Send to HOD" is explicitly labeled in its own page as a confirmation view, not an action, so this isn't hidden from whoever reads the UI. If a real staged review process (e.g. requiring DAPU sign-off before a course becomes assignable) is specified later, it's an additive change to this one module — a `status` field on `Course` plus a gate on when HOD's assignment screen shows it.
- **Alternatives rejected**: A separate `CourseStructure`/staging model mirroring the three nav labels — not built, for the reason above.
