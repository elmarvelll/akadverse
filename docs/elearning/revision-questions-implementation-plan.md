# Revision learning subsystem: implementation decisions

The user confirmed on 15 November 2026 that the question bank, teaching tracker, deduplication and FSRS components do not exist, and approved this teaching-pass rule: correct answer; independent evidence; adequate/strong reasoning; no review flag; recommended next step progress. All conditions are required against a server-saved AI evaluation of a server-owned practice question. Browser-supplied grades, expected answers, or pass flags are never accepted.

The AI engineer explicitly confirmed that question embeddings are independent of their ingestion/RAG vector space and delegated model selection. Selected first-bank contract: Gemini `gemini-embedding-2`, 1536 dimensions, canonical format version `revision-v1`. This uses the AkadVerse-side Gemini credential, not the AI microservice's private Vertex credentials. One model/version is locked for the bank; changes require a re-embedding migration. Normalize vectors and include full context, stem, answer, sorted options and explanation in comparison/judgment.

Use the installed E-Learning pgvector extension and database. Add canonical concepts derived only from verified material-analysis responses; server-owned independent practice attempts; immutable passed teaching events; durable generation jobs; global revision questions/variant links and embeddings; student-specific FSRS cards/review logs; provenance; and a notification outbox. Keep the webhook receipt in this same database for atomic final commits. Core identity remains an application-level reference as in existing E-Learning models. Notifications use the existing Core admin service after commit.

Use the first and only scheduler, official `ts-fsrs@6.0.0` DefaultScheduler/FSRS-7 defaults. Requires Node 24+. Do not hard-code initial memory values or reschedule existing cards when another teaching event reuses their question.

Question scope includes subject, curriculum, level, language, type, and normalized concept meaning. Exact hashes include complete canonical content. Scores below .85 are new candidates; .85–.92 and above .92 both require judgment before semantic reuse/variant decisions. Similarity alone never rejects. Persist separate useful variant records linked to their root, with per-student cards for the resolved question row; exact/semantic duplicates reuse a global row. Same-scope advisory locks and a locked preflight/recheck protect cross-delivery races without external calls inside a transaction. If the candidate set changes after preparation, fail retryably and redo preparation.

The synchronous webhook has an 8.5-second provider preparation budget, excluding database work; a 30-second sender timeout is recommended after live testing; embedding and bounded batched judging occur before a short final transaction. Dependencies/timeouts fail retryably, never bypass deduplication. Staging metrics must establish whether the sender needs a larger timeout; do not claim guaranteed latency from a model choice.

Student-facing practice submissions enqueue generation only after a persisted pass; generation runs in cron, never in the student's browser request. Material analysis is also queued when concepts need preparation, using the verified existing AI API and preserved validation contract. Feature flags default off for external workers until configuration/deployment checks are satisfied. An expired generation dispatch is uncertain: do not blindly regenerate a new body under an existing teaching key. Reconcile a completed receipt first; otherwise require review because the remote API has no stable regeneration replay endpoint.

Add admin operational metrics, durable alert delivery/backoff via existing admin notifications, safe correlation logs, reviewed retry/reconciliation controls, and student-owned due-card/review APIs. Routine duplicate events do not alert admins. Preserve original request/response IDs and recorded review history.

Re-audit follow-up, 16 November 2026: retain the existing implementation and already-applied migrations. Match administrator synchronous replay's route duration to the webhook, add a real-database exact-replay endpoint regression, revalidate locally, and update the handoff/deployment status. Do not rerun the nonrepeatable learning patch or create parallel learning models. Public producer callback and regular remote scheduler verification remain separate deployment requirements.
